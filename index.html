01 · Definition
What is the Travelling Salesman Problem?

Three pillars that define TSP and why it matters in computer science and the real world.

🧠

The Problem

Given a set of cities and distances between them, find the shortest possible route visiting every city exactly once and returning to the origin. Formally modelled as finding the minimum weight Hamiltonian cycle in a complete graph.

📊

Why It's Hard

TSP is NP-Hard — as n grows, the number of possible routes explodes factorially. For 10 cities: 181,440 routes. For 20 cities: over 60 quadrillion routes. No known algorithm solves it optimally in polynomial time.

🌍

Real-World Use

TSP appears in delivery routing (FedEx, Amazon), PCB drill path planning, DNA sequencing, warehouse robots, and network cable layout. Choosing the right algorithm directly impacts cost and time at scale.

02 · Algorithms
Greedy vs Brute Force

Two fundamentally different approaches — one trades optimality for speed, the other guarantees the best answer at enormous computational cost.

Greedy — Nearest Neighbor

Greedy Paradigm
✓ Advantages
  • Extremely fast — O(n²) time
  • Works for any number of cities
  • Simple to understand and implement
  • Usually within 20–25% of optimal
  • O(1) extra space needed
✕ Disadvantages
  • Does not guarantee optimal tour
  • Greedy traps — commits to bad early choices
  • Result varies based on starting city
  • Can be 40%+ longer than optimal in worst case

Brute Force — Exhaustive Search

Exhaustive Search
✓ Advantages
  • Guarantees the globally optimal tour
  • Checks every possible permutation
  • Acts as gold standard for comparison
  • Handles all edge cases perfectly
✕ Disadvantages
  • O(n!) — completely impractical for large n
  • 10 cities = 181,440 checks
  • 15 cities = 43 billion checks
  • Unusable in real-world at scale
03 · Complexity Analysis
Time & Space Complexity

How each approach scales with the number of cities, and what that means in practice.

Greedy NN
O(n²)
Space: O(n)
Approximate

At each of n steps, scan remaining cities. Fast enough for thousands of cities.

Brute Force
O(n!)
Space: O(n)
Optimal

Generates all (n−1)! permutations. Feasible only for ≤ 9 cities in practice.

Held-Karp DP
O(2ⁿn²)
Space: O(2ⁿn)
Optimal

Best known exact algorithm. Works up to ~20 cities. Uses dynamic programming.

2-Opt Heuristic
O(n²)
Space: O(n)
Near-Optimal

Improves a Greedy tour by repeatedly swapping pairs of edges. Used in practice.
